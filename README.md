## 二、主要功能

| 功能 | 能力与说明 |
| --- | --- |
| 🌐 官方优选 | 从官方地址库抽样检测 IPv4 / IPv6，按数据中心继续详细测试 |
| 🧩 自定义网段 | 输入 CIDR 后全量扫描指定范围，自动归一化并去除重叠地址 |
| 📄 导入优选 | 从 TXT、CSV 或网络 URL 载入 IP / 域名，支持自定义端口 |
| 📥 CF EDT 汇聚 | 读取导航中的优选域名、优选 IP、地区和运营商来源，合并去重后载入测试 |
| ⚡ 下载测速 | 支持单点、批量测速、测速地址选择和合格速度筛选，速度单位为 MB/s |
| 🔗 链路复验 | 对候选执行链路检测，支持复验后进一步筛选 |
| 🔎 结果处理 | 按条件筛选排序、一键复制、自定义输出字段及 CSV / TXT 导出 |
| 🚀 一键部署 | 在面板内完成 CFNext 部署，支持 Workers、Pages、前后端分离三种模式 |
| 🔑 凭据检测 | 集中管理 Cloudflare Token，检测 Account、Workers KV、Pages 权限状态 |
| 📡 订阅生成 | 按 Clash / Mihomo、Sing-box、Surge、Stash、Surfboard、Loon、Quantumult X 等格式生成订阅，支持复制、二维码、下载与预览 |
| ☁️ CFNext 上报 | 手动上报或扫描后自动上报，默认追加汇聚，提交后回读确认 |
| 🖥️ 后台运行 | Windows 隐藏到系统托盘；安卓通过前台服务和通知继续任务 |
| 🛠️ CLI | 提供交互配置、扫描、测速和导出；Linux 可选 systemd 定时任务 |
| 🔐 DEX 加壳版 | 安卓提供 DEX 加密自研壳实验包，业务 dex 加密存储，原生 so 零改动 |

**扫描范围说明：**默认官方扫描采用分片抽样，IPv4 按 `/24`、IPv6 按 `/48` 抽取候选；自定义 CIDR 输入才采用指定网段的全量扫描。关闭测速时只测延时，不再因测速阶段失败淘汰候选；结果数量按测速开关区分：开启测速时为测速上限，关闭测速时为扫描延时上限。

**CF EDT 拉取说明：**地区使用各地区的 `all.txt`，运营商按接口实际返回结果汇聚。运营商每源请求 10000 条，实际数量受上游限制；失效来源会显示失败记录，不能保证取得失效源或上游未公开的数据。

## 三、下载与安装

### 3.1 选择安装文件

从 `release_assets/2.0/` 中选择适合设备的文件：

| 文件 | 适用设备 | 使用方式 |
| --- | --- | --- |
| `NextKit-2.0-build25.exe` | Windows 64 位电脑 | 双击运行 |
| `NextKit-2.0-build25-android-arm64-v8a.apk` | 64 位 ARM 安卓设备 | 传到手机后安装 |
| `NextKit-2.0-build25-android-armeabi-v7a.apk` | 32 位 ARM 安卓设备 | 传到手机后安装 |

- **Windows**：需要系统具备 Microsoft WebView2 Runtime，软件通过内置窗口运行。
- **Android**：支持 Android 8.0 / API 26 及以上；按设备架构选择一种 APK。
- **包名兼容**：`com.nextkit.app` 与旧 `com.cfscan.app` 使用不同签名，手机升级时需先卸载旧版。
- 目录内同时保留 `CFScan-*` 等同内容旧命名文件，仅为历史兼容，新下载请使用上表的 NextKit 命名。

`SHA256SUMS.txt` 提供上述产物的校验值，下载后建议先核对哈希。

### 3.2 DEX 加壳版（实验性）

从 `release_assets/2.0-hardened/` 中选择：

| 文件 | 适用设备 | 状态 |
| --- | --- | --- |
| `NextKit-2.0-build25-arm64-v8a-hardened.apk` | 64 位 ARM 安卓设备 | 实验性，待真机验证 |
| `NextKit-2.0-build25-armeabi-v7a-hardened.apk` | 32 位 ARM 安卓设备 | 实验性，待真机验证 |

加壳版将业务 dex 用 AES-256-GCM 加密为 `assets/shell_payload.dat`，启动时内存解密加载，`libcfdata.so` 保持原样不做加密、改名或移动。已通过 8 项静态验证，包括业务 dex 分离、解密闭环、so 哈希一致、v2 签名与 16384 页对齐。

**动态启动尚未在真机验证通过。**不同安卓版本与模拟器环境可能存在差异，建议先装在测试设备上确认可以正常启动，再考虑日常使用。随包附带的 `shell_key.txt` 是解密加壳内容的唯一密钥，丢失后无法恢复，请勿入库或外传。验证明细见 [verify_report.json](release_assets/2.0-hardened/verify_report.json)。

## 四、快速上手

### 4.1 部署 CFNext 面板

1. 进入 **凭据** 页添加 Cloudflare API Token，并用「检测」确认 Account、Workers KV、Pages 权限状态。
2. 进入 **部署** 页，在「部署账户」中选择已添加的账户。
3. 选择本次操作：自动判断、更新现有部署或全新部署；再选择面板部署模式：Workers、Pages 或前后端分离。
4. 填写面板登录地址与密码。绑定了自定义域名时，订阅链接优先使用自定义域名，不再回退到本地 `workers.dev` 地址；安卓窄屏下登录地址与密码输入框并排显示。
5. 需要修改项目名称或部署路径时展开 **高级选项**，然后点击 **一键部署**。
6. 观察五阶段部署进度与近期日志，完成后点击 **打开面板**。

### 4.2 官方优选

1. 打开软件，进入 **官方优选**。
2. 选择 IPv4 / IPv6、测试端口、并发数量和延迟阈值。
3. 按需设置测速地址、合格速度、测速结果数量，并在开始前选择是否启用自动测速。
4. 点击 **开始扫描与测试**；启用自动测速时自动继续，否则按数据中心手动继续测试。
5. 在结果区筛选、复制、导出，或上报 CFNext。

失败剔除次数只影响严格模式的重试；关闭测速时每条候选只尝试一次，避免把确定性失败反复重试导致扫描过慢。

### 4.3 自定义 IP 段

在官方优选的 **自定义 IP 段（可选）** 中填写 CIDR。支持逗号、分号或换行分隔，例如：

```text
192.0.2.0/24
198.51.100.0/25
```

以上仅展示输入格式，使用时替换成实际需要测试的网段。

- 留空时使用官方地址库。
- 填写后全量扫描自定义范围，自动归一化主机位并去除重叠地址。
- 网段需与上方选择的 IPv4 / IPv6 一致。
- 单次最多 **16,777,216 个地址**、1024 个输入段，输入文本最多 64 KB。
- 仍按 Cloudflare 节点检测流程筛选；普通可达地址也可能没有合格结果。

### 4.4 导入优选与 CF EDT 汇聚

进入 **导入优选**，选择本地 TXT / CSV 文件，或填写网络 URL。也可以使用 **CF EDT 一键拉取**，勾选需要的来源后载入候选。

支持直接导入 **FOFA 下载的 TXT / CSV**。文件有 `ip`、`port` 列时，只读取这两列作为扫描目标，忽略 `host`、标题等其他字段；保留每行端口，按 IP＋端口去重。原有 IP、域名、IPv6 和 CSV 格式继续支持。

端口支持 `1` 至 `65535`，常用提示包含 `80`、`443`、`2052`、`2053`、`2082`、`2083`、`2086`、`2087`、`2095`、`2096`、`8080`、`8443`、`8880`。备用端口只用于没有端口的输入，不会替换文件自带端口。混合端口文件选择 **TLS 模式 → 自动识别（混合端口）**。详细格式见 [FOFA 导入说明](docs/FOFA_IMPORT.md)。

输入示例：

```text
192.0.2.10:443#示例节点
[2001:db8::10]:8443#IPv6 示例
edge.example.com:2053#域名示例
```

示例地址仅用于说明格式。载入候选后，按需选择 TCPing / HTTPing、TLS、链路复验和下载测速，再开始测试。

## 五、上报 CFNext

结果操作的「导出 / 上传」中也可选择**上报模式**和**上报内容**，与 CFNext 面板保持同步。默认追加汇聚，地址与端口使用标准格式。导入优选的 TXT 默认选择 IP:PORT、数据中心、源 IP 位置、地区、城市、ASN 号码和 ASN 组织，附加信息作为节点备注。复制默认不加 IPv6 方括号；结果导出采用固定格式，CFNext 上报独立使用标准 IPv6 格式。

### 5.1 手动上报

1. 如 CFNext 面板提供运行模式选择，请使用 **Worker 模式**；没有此选项的旧版可直接继续。
2. 在 Next Kit 中完成扫描与筛选，打开 **上报 CFNext** 或结果区的上报入口。
3. 填写面板的**完整地址**和登录密码；前后端分离部署填写**前端 Pages 面板地址**。若面板已绑定自定义域名，以自定义域名为准。
4. 选择结果范围，保持默认的 **追加汇聚**，提交上报。
5. 写入自定义订阅配置后回读，确认上报结果。

| 上报方式 | 行为 |
| --- | --- |
| **追加汇聚（默认）** | 保留原有自定义地址，将新结果合并、去重后追加 |
| 覆盖 | 用本次结果替换现有自定义地址列表，需手动选择 |

### 5.2 自动上报

保存面板信息后，在对应优选模块选择自动上报面板。任务结束时，由内置页面触发上报。

**请保持软件及内置页面运行，直到上报完成。**后台扫描可在页面断开后继续，但无人连接时不会自动触发页面上的上报流程。

### 5.3 历史版本兼容

已对历史样本中的 **58 份脚本及 ZIP 内 Worker** 完成本地上报验证，覆盖 1.x / 2.x / 3.x 的明文、混淆、小说、Pages 及前后端分离形态，适配登录格式、入口路径和配置接口差异。

验证包含登录、配置读取、默认追加、重复去重、错误密码拒绝、显式覆盖、回读及原有其他配置保留。完整清单见 [CFNext 兼容记录](docs/CFNEXT_COMPATIBILITY.md)。这是历史脚本的本地兼容测试，不代表每个版本均已线上部署实测。

## 六、常见问题

**为什么扫描结束没有合格结果？**
请检查输入地址、端口、TLS 设置和延迟阈值。Next Kit 按 Cloudflare 节点检测流程筛选，普通网站或仅 TCP 可达的地址不一定通过。示例中的保留地址用于展示格式，应替换成实际目标。

**为什么关闭测速后扫描仍然很快结束？**
这是预期行为。关闭测速时只做延时检测，测速类失败不再淘汰候选，每条候选只尝试一次。需要重试时请开启测速并调整失败剔除次数。

**为什么 CF EDT 拉取数量与导航显示不同？**
地区直接读取 `all.txt`，运营商按上游接口返回的数据汇聚。来源更新、失效、服务端返回数量限制及跨来源去重都会影响最终条数；请同时查看成功 / 失败来源统计。

**绑定了自定义域名，订阅链接为什么还是 workers.dev？**
当前版本已修复该问题：面板记录中存在非 `workers.dev` / `pages.dev` 的自定义域名时，订阅链接强制使用该域名，本地保存的旧完整地址只保留路径部分。如果仍看到免费域名，请确认面板实例的自定义域名记录是否已同步。

**CFNext 密码正确，为什么仍可能上报失败？**
先检查是否填写了完整面板入口，分离部署是否使用前端 Pages 地址。登录、读取、写入和回读属于不同步骤，请结合软件显示的错误阶段定位。兼容清单之外的新接口、站点访问限制或配置读取异常，也可能影响上报。

**如何恢复后台窗口？**
Windows 点击系统托盘里的 Next Kit 图标，或使用托盘右键菜单显示窗口。安卓通过任务通知或应用图标返回。后台运行仍受操作系统管理；退出程序进程或强制停止应用会结束任务。

**配置保存在哪里？**
运行配置文件名为 `CFScan-config.json`，这是为兼容旧版保留的名称；界面设置保存在顶层 `gui`。Windows 界面偏好另存于 `%APPDATA%/CFScan`，安卓保存在应用私有目录。分享文件、截图或反馈日志前，请先移除面板密码和其他私密信息。

**DEX 加壳版可以直接日常使用吗？**
建议先在测试设备上验证。加壳版只完成了静态验证，安卓各版本与模拟器环境下的 ClassLoader 注入、WebView、原生子进程和前台服务尚未逐一实测。如遇到启动失败，请优先改用正常版，并提供崩溃日志。

**CLI 是否包含全部图形界面功能？**
CLI 提供交互配置、扫描、测速和导出。自定义 CIDR 输入、CF EDT 一键拉取及 CFNext 上报、部署目前通过图形界面使用，未提供相应 CLI 参数。

## 七、源码与构建

```text
Next Kit/
├─ combined_refactor/   Go 主程序、嵌入界面、测试与 vendor 依赖
├─ app/                 Android 窗口、后台服务、资源与 DEX 壳源码
├─ tools/packer/        DEX 加壳打包、验证与密钥生成工具
├─ assets/              图标源文件与 Windows 清单
├─ scripts/             构建、验证及开源打包脚本
├─ docs/                功能验证、兼容清单和交付记录
├─ release_assets/      正常版与加壳版产物
├─ licenses/            第三方许可与通知原文
├─ BUILDING.md          完整构建说明
└─ LICENSE              项目许可证
```

**实际 Go 模块位于 `combined_refactor/`。**Windows、Android、签名及依赖版本的完整说明见 [BUILDING.md](BUILDING.md)。

Windows 构建：

```powershell
.\scripts\build-release.ps1 -WindowsOnly
```

完整构建需先配置自己的 Android 签名，再运行：

```powershell
.\scripts\build-release.ps1
```

Linux CLI 构建与启动示例：

```sh
cd combined_refactor
go build -o cfscan .
./cfscan -cli
# 后续按已保存配置启动：
./cfscan -cli qs
```

首次直接使用 CLI 时可能先生成配置模板并退出，填写配置后再次运行即可。

安卓 DEX 加壳版需要 JDK 17、Gradle 8.9、Android SDK 35 与 NDK，配置签名环境变量后运行：

```sh
bash tools/packer/run_pack.sh
```

脚本会先构建 release 与 hardened 两个变体，用 release 的纯业务 dex 生成加密 payload，再用壳 dex 替换 `classes.dex`，重新签名并输出到 `release_assets/2.0-hardened/`。前端资源已加密为 `static.bin`，修改 `combined_refactor/index.html` 后必须重新运行 `go run ./cmd/packstatic`，否则二进制里仍是旧页面。
